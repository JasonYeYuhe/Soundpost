Fold a per-capsule content fingerprint (note, place name, mood, soundprint — everything `NotificationCopy.Digest.lead` can render) into the identifier. Write the test so it FAILS before the fix; a test that only asserts "a request exists" passes today and proves nothing.
- **`rollback()` does not restore already-materialised objects.** This project learned it twice. Capture previous values and restore them by hand if `save()` throws, then surface the failure — a silent one means the user believes they fixed a typo that is still there. `ListeningConsentStore.set` is the pattern.
- **The whole card is a `Button`** (`ContentView.swift:128`, `.buttonStyle(.plain)`) and `CapsuleCard` merges its accessibility children. Do not nest a second `Button` inside it — restructure so the surface handles navigation and the play control is a sibling with its own hit region and accessibility element.
- **The detail view constructs its own `AudioPlayer`** (`CapsuleDetailView.swift:14`), so a gallery player can overlap detail, the resurface reveal, and capture. One owner; stop on every transition. `playingCapsuleID` must clear on natural completion AND on failure.
- **`AudioPlayer` ticks at 20 Hz** (`AudioPlayer.swift:96`). While playing, anything you add to a per-body path runs 20×/second over the library — and `displayed`, `upcoming`, `storageString` and `sealSignature` each already re-walk it.
